# 八成员长程研究的运行审计与修复

本次只修工程与证据采集，不发起新的 rollout，不改成员任务、通信条件、研究预算或组织提示。既有 intended / unintended 的冻结源码、输入、轨迹、失败记录、归档和语义判定保持原样。

本轮修复十一项可独立验证的问题，并统一普通与结构采集器的收尾逻辑：

1. **一个成员导出失败会跳过后面的成员。** 两条采集入口现在逐个调用原有严格导出校验；异常只记在对应成员名下，继续尝试其他成员。缺失 history 也明确记录。失败者不会被生成替代轨迹或获得连续性验证。导出清单记录成功与失败两部分，拒绝覆盖既有清单。独立历史 exporter 的默认行为不变。
2. **ATIF 异常会连带跳过 actor-evidence 清单。** 覆盖检查现在独立执行，即使标准轨迹导出失败，也记录哪些成员有原生数据、哪些有通过校验的 ATIF、哪些缺失。覆盖检查本身的异常单独保留，不再误记成 ATIF 异常。
3. **关闭错误可能覆盖最初的故障或被吞掉。** 保留第一个停止原因，把后续文件扫描、命令结果保留、原生会话关闭、投影保留和环境关闭错误按阶段与成员追加到 `shutdown_errors`。如果之前没有故障而关闭失败，最终结果明确变成失败；人工中断也不会被随后清理错误改写成另一个起因。
4. **关闭时的迟到用量可能改写停止原因。** 仍保存最后的响应与累计用量，但进入关闭阶段后不再发起新的预算停止。否则，运行时故障后的最后一条响应刚好超过预算，可能把实际停止原因错标为资源耗尽。
5. **最终摘要没有纳入校验清单。** 先写入 `collection-summary.json`，再生成文件校验清单；普通采集也保留该摘要。排除项按根目录相对路径匹配，不再误排除成员目录下同名的日志。大文件采用分块计算校验值。
6. **重复收尾可能改写旧结论。** 两条入口在任何收尾写入之前检查既有摘要、校验清单和 ATIF 清单；已有产物时拒绝重做。后续解释必须保存在另外的审阅产物中。
7. **结果盘点异常会跳过时间线盘点。** 两项独立尝试、分别保留异常；数学结果读取失败时仍可生成时间线清单。
8. **fatal 之后仍可能把原生压缩摘要和重置用量投影成正常响应。** 首次压缩信号单独记录并绑定原生事件；fatal 之后停止生成有效研究投影。原生 RPC 尾部和 session 文件继续原样保存，严格 ATIF 校验不放宽。正常关闭但没有 fatal 时，迟到用量仍保留。
9. **命令成功后，观测或通知阶段异常可能丢失已执行结果。** 完成后到保存结果之前保留待收尾任务；关闭时保存未送达的实际结果。如果结果已落盘、仅原生投递失败，则不重复生成同一次执行记录，也不重放命令。
10. **关闭队列中的 fatal 可能只记日志，最终仍报正常结束。** 关闭阶段显式记录迟到的原生错误与私有材料投递错误，不能报告为成功。先前已有故障时仍保留第一原因，且不执行关闭队列里尚未执行的工具调用。
11. **CI 选择了测试，却漏装测试实际需要的运行时。** 跨运行时注册检查同时依赖 Codex、Claude 和 Pi，原选择器只安装了发生改动的那个；工作站检查也缺少部分容器依赖声明。现在根据最终选中的测试补齐依赖：跨运行时检查安装三个运行时，采集器检查安装 Codex 和工作站，其余轻量检查继续保持原范围。这不改变研究 agent 的模型。

第一、二项直接对应这次导出中断与缺少覆盖清单；其他项由相邻路径审查和确定性回归案例验证，不能据此声称它们都已经影响了上一轮结果。代码清理集中在统一逐成员导出、覆盖检查与封存，以及拆出命令保留和末尾事件处理，避免两条入口继续产生不同的错误处理行为。

## 上下文压缩：复现了配置缺口，尚未修复长程阻塞

先前结果报告中的“压缩已配置禁用”应理解并更正为：实际设置是 `model_auto_compact_token_limit=2147483647`，这只是一项极大的阈值配置。官方配置文档也把该设置定义为自动压缩触发阈值，并没有把它定义成禁用开关。[官方配置说明](https://learn.chatgpt.com/docs/config-file/config-reference)

使用与研究相同的原生 CLI 0.166.0、`openai/gpt-6.1-sol` 配置及相同阈值，在本地 HTTP 模拟端点上运行了两个确定性案例：

- 模拟响应报告 10 个输入 token：正常结束，没有压缩事件。
- 模拟响应报告 300,000 个输入 token：出现 `contextCompaction`，原有采集器按注册规则报告 fatal；原生会话与事件均被保留。

这些都是人工构造的协议响应，**线上模型调用为零**。第二个案例证明巨大阈值不等价于压缩已禁用，不证明模型支持该输入长度，也不证明实际研究中的两次压缩由同一个精确阈值触发。实际失败前最后报告的输入分别约 149k、177k，原生有效窗口记录为 258,400；不能仅凭这些计数推出完整内部触发路径。

本次保留压缩即停止的规则，没有通过删除保护断言、伪报更大的窗口、自动换模型、重开会话或注入研究摘要来让实验继续。因此**不能声称 90 分钟运行问题已经修好**。后续需要明确并验证上下文管理条件：如果允许压缩，须单独记录压缩边界、压缩前后上下文与用量，并验证导出及角色连续性；如果坚持禁止压缩，则应验证原生实际行为与可用窗口，而不只检查配置文件中的大整数。

原生压缩记录还揭示了实验条件问题：CLI 0.166.0 的本地压缩替换内容使用“另一个语言模型已研究过这个问题并给出摘要”的包装文字。即使没有分工或领导者提示，该文字仍可能给 unintended 引入额外的同伴线索。它属于运行时私有记忆处理，不是成员自发汇总的证据。修复后本地原生探针验证了：该边界触发后没有新增研究响应投影，原生开始、结束和替换上下文记录均留下。

另行测试的提供方名称、remote-compaction 能力声明等配置未建立可用的中性压缩路径，因此没有接入生产代码。一次内置提供方探针忽略了预期的本地基址并向默认端点发出未授权请求，返回 401；它没有调用成功的线上模型，没有使用真实凭据，也不能作为本地端点验证成功的证据。完整失败日志一并归档。未来支持长上下文仍须在两组相同、明确登记的条件下验证，不能把这次收尾修复等同于已支持 90 分钟连续研究。

## 验证与适用范围

回归覆盖包括：首个成员失败后继续导出后续成员、缺失成员明确标注、拒绝覆盖旧导出、人工中断不中途吞掉、结构最终报告仍生成部分覆盖清单、初始故障与多个关闭错误并存、关闭阶段新增超额用量不会改写故障原因。原有八成员持续研究和异步文件唤醒的原生离线案例也包含在选择的检查中。

首次检查误用了本机默认的旧工作站镜像，七个容器案例在启动时因缺少 `strace` 失败；新加的回归案例通过。随后使用本轮研究的已验证镜像重新执行，61 项选定测试全部通过（含实际原生会话、容器及脚本化本地响应的八成员案例）。详细结果和原始失败日志分别保留，见同名 JSON 审计记录。

进一步修理和合并主分支后，最终源码的 149 项选定测试全部通过，另通过语法、输入清单、输入目录与轨迹格式检查。新增回归包含压缩和关闭同时发生的六种边界组合、三个命令结果保留失败位置、重复收尾不改字节以及末尾 fatal 不得误报成功。任务、持续研究策略、文件通知策略与模型网关配置的源码均与修复前逐字节相同。

最终代码的测试记录、确定性原生探针、源码校验值与 CI 状态见同名 JSON 审计记录。修复影响新代码的收尾行为，两条采集入口共用逐成员 ATIF 导出与封存。已有冻结执行副本不会随主分支修改。

首次源码 CI 的 149 项选择中出现三个缺少 Pi / Claude 安装的错误，并按既有规则跳过六个未安装可选历史 Codex 版本的案例。该失败未被重标为成功；日志另行保留。补齐测试依赖声明后，本地重新执行 49 项受影响的原生与选择器检查，全部通过。此次补修只影响测试依赖和新增断言，采集器运行逻辑不再改动；后续 CI 状态与补充证据单列在 JSON 索引中。
