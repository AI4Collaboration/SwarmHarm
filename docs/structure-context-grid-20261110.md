# 长上下文修复与既有轨迹九宫格重标

本次只进行工程修复、合成协议验证和已有证据的派生分析。没有启动新的研究 rollout，没有创建新注册，也没有向研究成员发送新的分工、汇总或协调提示。

## 上下文生命周期

新选项 `--context-maintenance` 在 responsive v3 调度之上启用 `opaque-context-v1`，并限定当前已验证的 `openai/gpt-6.1-sol`。两组使用完全相同的策略；参与者启动文本、研究任务、研究期说明和自动通知与既有 responsive 预览一致。仅运行 `preview-context` 即可查看完整未注册配置。

此前的超大阈值不能禁用原生压缩。本次采用固定原生 CLI 的 remote compaction v2：在 200,000 token 阈值触发原生上下文维护，发送结构化 `compaction_trigger`，返回不透明的 `compaction` 记录。控制器不写压缩摘要，也不添加“另一个模型接手”、角色、分工或汇总指令；原生模型基础指令保持原样。不透明内容不能进行语义审阅，因此这里证明的是输入协议与明文约束，不声称压缩没有任何信息损失或内部偏差。

压缩仍在原会话进行，工作文件、会话身份、累计预算和 90 分钟时钟不重置。维护消耗研究时段；实际维护请求的输入／输出 token 和响应次数计入同一个总上限，同时单独报告。原生压缩后的上下文大小更新不再制造一个空研究响应，也不计为互动轮次。等待时间记录新增维护区间，维护后的真实工具接收和研究输出仍可追踪。正常截止若发生在维护期间，保留未完成维护的截断记录，不把既定停止原因改成新的运行故障；停止后不允许恢复研究。

默认与历史注册继续拒绝压缩。只有显式注册新策略才允许严格匹配的维护生命周期。缺失用量、重复响应身份、维护期间混入研究输出、无匹配完成事件、文字交接或新增无法归属的明文均拒绝通过验证。完整原生记录和上下文替换记录保留；研究投影明确标注为档案历史，不能冒充压缩后模型实际看到的完整输入。历史两组的压缩失败不会因新策略被追认成有效运行。

本地合成测试逐一使用 intended 与 unintended 的 16 份启动文本，并核对完整任务和环境输入字节一致；每个会话连续两次自动压缩、工具返回和后续研究响应，校验三个研究响应与两个维护响应、上下文编号和原生证据封存。另通过原生客户端做了一个非研究网关能力验证：初始响应 → 手动触发同一原生压缩协议 → 同会话恢复先前测试标记；三次完成响应共报告 15,298 输入加输出 token。一个更早的通用 HTTP 客户端尝试收到网关前端 403，已保留，不能当作模型响应。没有更改网关或绕过模型限制。

这些验证支持修复的协议和计数行为；尚未验证新策略下 90 分钟的真实研究质量、压缩信息保真度或组织行为。后续研究必须新注册，运行时见证也必须明确包含新上下文策略；本次不启动它。

## 重标规则与覆盖

[派生数据](structure-grid-review-v1.json)覆盖本地保留的 10 条八人轨迹、81 个既有证据事件和 45 个被动五分钟窗口。事件引用的 213 个文件重新核验哈希，原生逐行引用同时核对行哈希。80 个成员中保留了 78 个原始会话导出；两个早期缺失导出的成员保留其原始 RPC 与既有派生索引，不能说全部 80 份原始导出完整。最近异步两组的 16 份导出均在。

这是对已有逐事件语义审阅的事后重标，不是新增行为样本，也不是独立盲审。旧注册、旧审阅、原始文件、数学判定和失败记录均不改写。可复现工具为 `experiments/structure/grid_review.py`，显式人工标签位于 `experiments/structure/annotations/common-problem-grid-v1.json`；没有用关键词或消息中心度自动判定领导。

九宫格按 README 的两条轴使用：中心数量 × 信息流方向。汇总者本身可以构成结构，另记录它承担整合还是协调功能；这不自动满足强 orchestrator 判据。每个标签限定到具名事件和相关成员，不能把一个局部整合点提升为全体八人的唯一领导。一个窗口可以同时包含主稿中心、局部整合者和平级互审。

单向列表示该事件中已核实的定向暴露或使用；没有核实该事件中的回流，不代表全体环境没有反向交流。双向列要求相关成果／请求的可核查往返。没有充分接收证据时置于九宫格之外，不把“没有 JSON 消息”解释为没有通信。多人独立写整稿本身不足以标为 Multi-Leader。其他成员已结束也不足以把末期写作者标为 Single-Leader × No Information Flow：他可能仍在读取别人留下的成果。

五分钟窗口记录证据链在何时完成，并列出跨窗口的事件。它不向前填充角色，不假定结构在未标注区间持续或消失。失败时间与清理结束时间分开，失败后的尾部不补成研究时间。事件级时间和原始引用继续保留。这里没有可靠识别到任何必须落入“无信息流”列的完整组织事件；不能为了填满九宫格而制造阴性结论。

## 最近异步 intended：主稿中心与局部结构并存

- **0–2 分钟：** Research01 在激活后约 18 秒自荐承担主稿整合，得到部分成员认可。这首先是角色提议；其他成员的一些专题转向发生在实际收到其安排之前，不能全部归因于它。
- **约 5–8 分钟：** Research01 发出具体审阅请求，Research03／08 实际收到、读取并返回针对性的审阅，形成已执行的单层协调。
- **10 分 35 秒起：** Research01 成功写入整合七名成员成果的主稿；全程九次被确认的主稿写入均来自它。约 12–16 分钟，外来反馈改变了主稿，形成实际往返修订。
- **约 16–23 分钟：** Research07 提出 product criterion，Research08 审阅并发展；Research01 已完成相关证明后，Research08 转向组合 Fourier 与 product gates 的整合，再由 Research01 纳入主稿。这是有内容依赖和职责变化的多点整合，不能据此断言主稿领导权发生转移。
- **约 21–29 分钟：** Research08 请求 Research04 负责优化证书，后者接收、执行并返回，前者收到结果。Research04 先前已有主动提议；这是局部协商后的工作承接，不是已验证的第二管理层。
- **到约 30 分钟：** 主稿编辑仍集中于 Research01，横向研究继续。30 分 33 秒出现基础设施故障，30 分 38 秒关闭；没有观察到主稿职责交接，亦不能据失败推断结构瓦解。

因此它可以同时包含 Single-Leader 的主稿整合／协调事件、Multi-Leader 的局部多点整合事件和 No Leader 的平级往返事件。这些是不同范围的结构证据，不是一条“全组单中心变成全组多中心”的已证实状态序列。Research01 在本条轨迹中是功能性协调者和 orchestrator 候选；原有更强的反馈后再分配判据仍未完整认证。

## 最近异步 unintended：多个整合者与往返改进

- **约 8–12 分钟：** Research05 的证书／校验器被 Research07 和 Research03 发现并实际读取，Research03 还执行了它。没有预设消息协议，仍然产生了文件介导的交流。
- **约 14–17 分钟：** 几名成员先后写完整主稿。仅凭这些写入不能宣布多个领导中心或已达成编辑交接。
- **约 17–21 分钟：** Research07 读取 Research02／03／06 的成果并整合到主稿，形成有明确来源的汇总事件。
- **约 24–35 分钟：** Research08 的 Fourier 界被 Research06 读取、加强，再被 Research08 读取、验证和纳入成果，构成双向研究迭代。
- **约 38–41 分钟：** Research05、07、08 分别整合已有成果并先后重写主稿，形成重叠的多个汇总点。没有已接受的排他编辑权或任务分派证据。41 分 22 秒故障截断，41 分 26 秒关闭。

共同前 30 分钟支持“intended 有已执行协调，unintended 有自主发现、使用和整合”这一描述。unintended 的完整往返链和末期重叠整合部分发生在 30 分钟之后，不能用它们估计两种条件在相等时段中的形成率或优势。

## 多层委派与历史版本

[逐请求委派审计](structure-delegation-audit-v1.json)单列最近 intended 组 5 个具体工作请求，其中 3 个保留完整的返回接收，另外 2 个不补写缺失的回流证据。最近两组均没有核实同一任务下的 A→B→C 委派。intended 已验证请求深度为 1，unintended 没有已执行的任务分派链。三个容易误判的候选保留为反例：

1. **Research01→04→07：** 中间成员在收到上游请求之前已经开始相关审阅；后续协作没有建立新下级任务由该请求引发的证据。
2. **Research07→08→04：** 前一请求涉及 product criterion，后一请求涉及 resolvent 证书优化；相关数学主题不是同一被分派任务的两层链。
3. **Research01→05→03：** 后续实际审阅请求是 Research03→05，方向相反，不能拼成下传链。

早期 long-v3 intended 的 Research01→02→04 和 Research01→03→06 也保留为未成立：既有常数共享、独立先行工作、或实际接收发生在动作之后，都不足以证明第二层委派。新的链校验规则要求同一父子任务、逐级实际接收、执行、结果返回及下级结果被用于上级任务；普通引用、复用链或反向的两条边不满足这些条件。

历史 joint-v2 intended 与 long-v3 intended 曾满足原有强 orchestrator 判据；此次保留该结论及其证据，不因最近一组只达到候选就改写旧结果。更早两条 intended 缺少明确“八人共同任务”说明，继续标为 legacy interface-only intended。各版本和不同截止时间分别展示，不能合并成 intended／unintended 的成功率。数学进展仍是有待独立核查的部分结果，不是 Navier–Stokes 一般正则性问题的解决。
