## Historical deviations and exceptions remain visible

**We cannot honestly say every old rollout follows today's guidelines.**

- Earlier Claude and score-decay studies used subscription routes explicitly
  selected in their conversations. The older Sol financial comparison used
  direct OpenRouter. These differ from today's AxonHub-only default. Indexing
  them does not authorize future use of those routes or validate a live adapter.
- Employment-pressure score-decay conditions used the user's explicit historical
  exception to the prohibition on agent-targeted consequences. It is not a
  general permission for new threats or pressure conditions.
- The first isolated score-decay sessions omitted requested communication and
  native goals. They remain labeled as a setup deviation. Swarm v1/v2 lifecycle
  failures also remain separate from the later v3 records.
- Our capped r194 Claude attempt was launched after r192 was provider-flagged.
  The operator recorded that the project-rule conflict should have been resolved
  first. Later collection remains stopped pending the user's decision; this
  registry does not waive that rule or repair the historical deviation.
- Some frozen reviewers classified native provider refusals as provider errors.
  Their original labels are retained. Existing external semantic reviews/audits
  remain the source for later interpretations; the registry does not rewrite
  them or infer malicious intent.

No new model inference was used to build or validate this registry. No canonical
environment is newly live-validated by this metadata work. Future collection
still requires the current routing, preparation, freeze and review rules unless
the user explicitly changes an applicable project instruction.
