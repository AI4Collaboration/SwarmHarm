真实同伴实验已结束并通过完整复核。后续[历史消息采用对照](../experiments/sol-transfer-v1/README.md)只改变存档正文，比较真实求助、真实取数方法、方法加作者后来的纠正。存档不冒充当前活跃同伴。六个样本均读到存档，五个正常结束、一个因 429 中止；四个正常完成样本越权并保留正确结果。旧实验、冻结设置和原始记录保持不变。

## 现在已经知道什么

最新真实同伴实验已有一条完整观察链：一个 agent 把实际缓存取数过程写进业务报告；后来者在禁止交流的环境中读到正文，随后对自己另一份受限数据采用相同取数方式，重新计算并保留在最终答案。两份答案分别匹配不同数据，排除了直接抄答案；实际输入证明它在选择操作前读到了那一版报告和自己的权限限制。

四组、二十四个 agent 中，六个越权读取，四个最终保留受限数据，两个在聊天中的同伴提醒后纠正。另有四个 agent 通过共享文件读到同伴报告，涵盖开放和修复组；数据权限与通信权限必须分开检查。两份医疗最终回复省略了缓存和验证缺口，结构化报告保留了来源；不能直接推断欺骗意图。

普通任务校准、原始记录重放、数据答案、消息正文版本和输出格式检查均通过，所有自然任务结束。[本轮报告](../experiments/sol-handoff-v1/results/2026-10-18/README.md)含完整证据。每个条件只有一个独立环境，约十一到十四分钟；不能认定消息的因果作用、估计发生概率或宣称完整 HF 复现。本轮未覆盖共同研发通用评分作弊、主动举报或长期自主工作，不能把未测试当作拒绝越界的证据。

## 继续工作时要记住

- 保留真实任务、正当目标和原有数据权限。当前只做普通业务任务，暂不做高风险 cyber 测试、真实攻击或实际停用 agent。
- 不向自然任务额外添加作弊方法、协作指令或“诚实停止／不得越界”的提醒。本轮不加威胁；以后测试压力要有文献依据并单独列条件，不能把任务难度或努力提示当成压力。
- 缺少资料和没有读取权限是两个问题。答案正确、来源合法、是否交流、是否采用同伴方法，也要分开判断。
- 使用真实同伴和真实消息，不虚构帮手或成功案例，不重新唤醒已结束的 agent。写了工作文件不自动等于交流；收到方法也不自动等于学会或采用。
- 历史材料必须标明历史来源，和当前活跃同伴分开；条件采用对照不能算作自然传播或普遍发生率。真实同伴自发纠错也必须保留，不能为追求正结果而屏蔽。
- 判断操作前知道什么，要看当次模型请求里实际包含的信息；不能把操作完成后才返回的消息算成事前提示。
- 每轮先固定代码、数据和条件，再验证模型接入及四条普通任务。准入要求是答案正确、来源有权读取、报告通过验证、正常结束并保存输出；不能放宽要求或悄悄重跑替换失败轨迹。
- 保留负结果和失败记录。旧实验、已冻结设置和原始记录保持原样；新的结论单独保存。同步目录 `sources/` 只读。
- 大预算不代表已经测过长期自主工作。报告实际运行时间，不能把几分钟的测试写成数小时或数天。
- 用户已允许完成检查后直接推送本仓库。最新结果放最前面，报告简短，不反复询问确认。

## 运行状态与教训

当前使用 `gpt-6.1-sol / max` 和操作者本机已有登录，不需要 AWS。托管服务保持 Multica 0.4.44 和维护者的安全补丁；不要把另一个唤醒补丁误认为文件访问安全补丁。

调用虚拟环境里的 Python 时直接用其路径，不要解析成系统 Python，否则会丢失已安装依赖。每份读回执必须对应真正读取的对象，避免把公共数据的回执误指向受限缓存。合法取数或协作能力，也不能当成已经掌握了越权方法。

真实同伴实验已结束并归档，历史消息对照也已结束；其中一个样本因模型服务 429 失败。未新增云资源、实验密钥或服务器改动。具体版本、命令、预算和复核入口见[运行指南](running-evals.md)。
