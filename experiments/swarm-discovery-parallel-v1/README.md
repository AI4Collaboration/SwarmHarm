# Parallel Stage 1 repetitions

**27 October 2026:** preparing a registered, allowance-bounded parallel suite.
The [fresh longer run](../swarm-discovery-window-v1/RESULTS.md) produced one useful
cross-job exchange after the five-minute cutoff. Repetitions are needed before
making a frequency or model comparison.

Eight cells cross DeepSeek/Novita versus GLM Prime/Alibaba, 5 versus 15 minutes,
and natural business-client visibility versus repaired job-only visibility.
Each trial starts four fresh concurrent contexts with the exact archived initial
messages, files, fixtures and plan. The repaired control changes actual record
visibility without changing subject prompts. No peer/channel hints, pressure,
seeded notes or resumed histories are added. A stable hashed order interleaves
cells within eight-trial blocks; up to 32 blocks are registered.

The controller starts up to four trials at once, subject to available memory,
disk, current shared-key allowance and local EOD. An upper queue limit is not a
promise that all trials will run. Incomplete final blocks stay in the report.
Every admitted request has an uncached conservative price reservation, protected
by a process lock and fsynced records. Actual reported costs settle reservations;
unknown requests retain theirs and hold new dispatch within this suite. Other
users' settings, processes and credentials are untouched. Live balance checks
cannot prevent another user from spending between checks.

The expensive GLM condition has a catalog alias rather than a guaranteed
immutable snapshot; the selected endpoint names its 20260921 revision. Requests
pin Alibaba and require the served model ID to match. Model and provider effects
are confounded. The fixed four-job template also limits generalization. These
are coordination experiments; neither ordinary cooperation nor a visibility
violation alone establishes harm or general alignment.

The unchanged v3 collector, isolated Docker adapter and business mechanics reuse
previously validated FIFO, positive-exchange and repaired-visibility controls.
Nine new tests cover the factorial plan, simultaneous reservations, settlement,
unknown holds, overruns and deadlines. Per-trial audits preserve original scores,
check exact route identities, distinguish self-updates from cross-job replies,
and export schema-validated ATIF with native history continuity. A grader failure
is unscored. The report includes every launched trial, valid denominators,
separate unscored counts and descriptive trial-level Wilson intervals.

```sh
python experiments/swarm-discovery-parallel-v1/test_suite.py -v
python experiments/swarm-discovery-parallel-v1/run.py prepare --root NEW_SUITE --backup NEW_BACKUP --inputs-from ARCHIVED_V3_RUN
# Publish exact registrations before running the one-shot controller through the private credential wrapper.

```

`controller-status.json`, `report.json`, `REPORT.md`, per-trial recovery indexes
and `allowance.json` support recovery. Never restart the controller or a started
trial. Never release unknown reservations or replay ambiguous API requests.
The clocks govern new admissions only; no process is killed, paused or restarted.
Raw backups remain on this Mac. No EC2 or hosted coordinator change is involved.
