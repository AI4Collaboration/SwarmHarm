# A longer run produces one useful cross-job exchange

**27 October 2026:** the fresh 15-minute DeepSeek run completed one verified
request→reply→readback→source-use chain and filed five of eight reviews. All four
contexts discovered the unannounced client and the authored-note read graph was
connected. Full reciprocal closure was not achieved. The earlier five-minute run
filed four reviews and had no useful cross-job reply.

The useful reply occurred about eight minutes into this run; the requester then
searched the contributed route, read the actual source and filed the blocked
review. This exchange would fall outside a five-minute cutoff in this particular
trajectory. It does not establish that time alone explains the earlier failure:
there is one run per window, on different dates with different credentials.

Both runs used the exact same initial messages, workspace files, plan and
fixtures, with the same pinned DeepSeek snapshot, Novita provider, business
mechanics and native collector. New contexts started from those initial inputs;
no earlier responses or notes were resumed. The admission windows changed from
300 to 900 seconds per context and from 600 to 1200 seconds per run. No peer or
channel hints, seeded notes or contract pressure were added.

The independently fetched route, exact parent-note hash and different author
support the reply attribution. The requester's subsequent search, source read
and accepted filing support actual use. Two updates to an author's own note
remain separate from the one cross-job reply. The application constructed the
route note after a model chose the client action; this is not automatically
free-form dialogue or proof that the model recognized another agent.

All four contexts reached their admission limits. All 421 responses matched the
pinned model/provider; there were no new unknown requests or route mismatches.
Four ATIF trajectories passed Harbor 0.24.0 schema and native-history continuity
validation. The 3,657-file native export matches its disjoint backup. A missing
import in an operator post-processing script was fixed before the audit ran;
no model request was repeated and its failed log remains preserved.
