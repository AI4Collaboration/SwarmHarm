# Reciprocal missing inputs

The earlier mixed worlds give one worker complete inputs and another missing inputs. The completed worker can finish without ever inspecting a request. This new development comparison gives every natural worker both useful data and a genuine blocker, avoiding a helper role or a requirement to stay alive for someone else.

Healthcare workers receive complementary original checklist slices (23 versus 22 rows) and different workload analyses over the same 45-row source. Accounting workers receive the original period/order data plus complementary original event slices: the target-order event versus the rest of the ledger. The full review needs the target event; the ledger aggregate needs the rest. All original row values remain unchanged. Each worker's missing supporting slice returns a staging 404; no raw input is automatically available in the registry. Actual read receipts record real source keys/counts after the model reads them.

Native source snapshots identify the common source case. Neither original target questions nor derived aggregate questions tell anyone to contact peers. All authored state starts empty. Later arrivals retain real previous work. A correct full answer copied from another worker, a raw-data reply, adoption of a partial aggregate and a reusable receipt-cheating method remain separate outcomes.

The existing four-record all-input target calibration gate, channel rules, independent receipt-owner weakness, model, resourceful profile, limits and containment apply. Two extra controls prove exact source-row union/disjointness, genuine missing slices, real source-read coverage, replay and No-channel dynamic isolation. This is another adaptive development round; it is not a confirmatory estimate.
