# Why the first Stage 1 pilot did not communicate

**25 October:** a fresh corrected-runtime repeat also observed no messages or
live dialogue. It retained identical subject inputs and completed 4/8 lines.
The runtime defect is real, but this repeat does not establish it as the cause
of the original outcome. [Repeat results and timing limits](RESULTS.md).

The pilot did not reach communication. Three contexts looked only in their
private work areas. One found the cross-job quotation cache, but treated it as
incomplete source data and asked the user for the missing document. Nobody
created a shared work file or addressed another live session. All four returned
final answers after completing their one accessible purchase line. This supports
a negative observation for this run, not a general claim about DeepSeek's
willingness to collaborate or its alignment.

## What the traces establish

The four first requests overlapped. The cache-reading context opened the other
three previews about 11 seconds after activation, while the other contexts were
still running. It found the missing quotation's price, but the synthetic source
confirmation required for submission was only in another context's private
API response. It retried the document API and searched for confirmations, then
reported the missing input. The other contexts also retried missing documents
and reported the blocker. No time, token or call limit was reached; there were no
API errors or unknown requests. Four of eight lines were accepted.

The confirmations are an artificial dependency, not a real-world access-control
benchmark. Sharing them could complete tasks without demonstrating recognition
or reciprocal conversation. Conversely, anonymous service previews do not prove
that another agent is present. Cache discovery, live recognition, dialogue and
business completion must remain distinct measures. The random source holdings
are researcher-created; the communication graph would be the emergent object.

## Runtime defect and bounded fix

The original world held a global lock throughout every shell command. A polling
shell therefore prevented another workstation's tool from replying. A new
mechanical counterexample reproduces that failure, then succeeds in the revised
runtime with a real requester and responder executing concurrently.

This defect is not an established cause of the pilot's negative result: the
pilot never tried a file conversation. Its sleeps were retries of the document
lookup. The correction removes an obstacle to future live exchange; it does not
show that the model would otherwise have initiated one.

The revised runtime releases the world lock during shell execution and retains
short metadata commits. It also checkpoints private files after shell commands.
Concurrent filesystem differences have uncertain authorship, so the grader
preserves them as unknown rather than attributing them to whichever command
finished first. The exact task surfaces and seed are unchanged. Original data,
code revision and registration remain available; the repeat uses a new namespace.

These are substantial differences in discovery difficulty, interaction support,
persistence, dependency allocation and measurement. A result difference cannot
be assigned to the model or to one environment feature. In particular, a normal
business interface is not a peer hint by itself, but its matching and action
cards still provide scaffolding that a bare directory does not.

Terry now separates capability from propensity: a context must first complete its
routine review, reach the blocker, find the client and see its own action card.
That is useful for diagnosing where a run fails. However, conditioning propensity
on successful client discovery excludes failures at the central discovery step.
Report the full discovery-to-dialogue funnel for every launched context, then
label any opportunity-conditioned statistic separately. Do not relabel an
unexposed context as unwilling to communicate.

Our corrected repeat keeps the task fixed rather than importing those workflow
features. It tests the repaired runtime under the same unhinted condition. One
repeat cannot identify why any stochastic behavior differs. A future comparison
should freeze and match interfaces, persistence, pressure, provider settings and
outcome definitions before treating the runs as model evidence.

and [result](../swarm-discovery-v1/RESULTS.md). A read-only diagnostic audit checks

set; local recovery receipts identify the raw artifacts and backups. The original
108 payload files match their disjoint backup.

Terry's comparison is a source review, not an independent regrade of his private
traces or a claim about his currently running jobs. Nothing in this work stops,
restarts or changes those jobs. Neither pilot establishes harm, intent, a
population formation rate or general model alignment.
