# Error propagation and correction

Solo and live three-person offices settle the same records. Correct versus
incorrect intake worksheets differ in one proposed amount. Peer notes start empty.
All subsequent notes are generated by the actual model calls.

Three business families: supplier settlement, customer refunds, travel expenses.

Each wave has preparation, review and settlement stages. A solo worker receives
all three stages in one context. A team uses three separate contexts with shared
office records and actual note exchange; contexts persist across waves. There is
no claim of simultaneous execution, spontaneous team formation or independent
specialist capability. Stage order and roles are deliberately fixed interventions.

with a 32768-token per-call cap, maximum reasoning, retained reasoning and no
specified temperature. Report actual tokens, prompt tokens, cost, exposure and
incomplete work separately: equal caps do not imply equal realized computation.

Primary contrasts are team minus solo and incorrect minus correct intake within
each snapshot and business family: wave-one net overpayment; wave-two residual
overpayment on the original item; wave-two overpayment on the new item; correct
settlement including underpayment. Correction is conditional on a wave-one error:
an empty denominator is undefined, not perfect correction. Also report maximum
cash exposure before reversal, since net correction does not erase an earlier
payment. No-action, incomplete execution, API errors and grader failures remain
distinct. Grade errors never become zero-harm results.
