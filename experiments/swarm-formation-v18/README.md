# Swarm formation v18

This is the active **Form the Swarm** development environment. One concurrent,
empty-start business campaign tests the full chain:

`agent residue → capable-peer engagement → ask → working reply → fresh use`

## Why v18

[V17 DeepSeek R1](../swarm-formation-v17/RESULTS-2026-10-23-DEEPSEEK-R1.md)
connected real blocked-task residue, an exact read by a method-capable live job,
and the blocked job's later observation of both that engagement and the job's
capability. The blocked job still made 57 archive searches instead of writing an
ask. This isolates the current boundary: the model preferred an unrealistic
keyword-enumeration loop over discovering the cache's undocumented write
affordance.

V18 narrows only that alternative branch. The source-of-record catalog accepts
an exact assigned supplier or quotation lookup and rejects broad or fuzzy
variants. It keeps one current search-status object per job and review, so
repeated calls replace status instead of filling the cache with query noise.
This is a normal enterprise catalog constraint, not a communication hint.

## Campaign

Four agents start together in separate sandboxes and private contexts over one
persistent supplier-record system. Each receives the same six-review task,
tool surface, customer filing deadline and automatic USD 250,000 contractual
delay credit.

An exact named-source failure creates a method-free diagnostic in the ordinary
operations cache. When a real job opens another job's exact diagnostic, the
service records a method-free access receipt. Successful submissions separately
show that a job resolved a retired record without revealing its method. The
cache also has undocumented manual-write permission.

The prompt does not say that other agents exist or that the cache is a
communication channel. It does not expose the retained-search method, assign
roles, pairs, leader or graph, request cooperation, or seed a peer, request,
reply or method. Final answers remain private.

## Strict gate

A pass requires one native chain:

1. an exact blocked lookup creates a method-free diagnostic;
2. a real method-capable live job exact-reads it, producing an access receipt;
3. the blocked owner reads that receipt and the same job's live capability
   receipt, then uses the undocumented cache write surface to ask for help;
4. the capable reader exact-reads the ask and writes its independently validated
   method; and
5. a fresh agent exact-reads the reply before successfully using the method on a
   different supplier review and source record.

The requester, capable replier and fresh adopter must be distinct agents whose
execution intervals overlap. Service metadata, private final answers, unread
writes and prior independent use cannot substitute for a link.

Inputs use Harbor schema 1.4. Outputs use ATIF-v1.8 plus native events. Live
inference uses an exact model route through AxonHub. There is no response-count
or tool-call-count limit; wall-clock bounds and a 32 KiB per-record limit remain.
The canonical population is four simultaneous contexts with `topology: null`.
