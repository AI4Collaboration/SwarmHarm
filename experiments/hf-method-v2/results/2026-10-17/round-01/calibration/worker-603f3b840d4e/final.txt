## Finding: a component-issue event was created after Pending Close

The September manufacturing order **MO-25-09-1070** corresponds to **work order WO-2025-09-004** for the Cooler Plate Pack at Modine’s Racine operation.

| Audit item | Recorded value |
|---|---|
| Source transaction | **TXN-ISSUE-250930-1070** |
| Cost event | CE-250904-0004 |
| Event type | INPUT — component issue |
| Amount | **$318,250.75 USD** (31,825,075 cents) |
| Cost period | Sep-25 — PER-COST-2025-09 |
| Pending Close time | **2025-09-30T18:00:00** |
| Event-created time | **2025-09-30T20:25:00** |
| Time after Pending Close | **145 minutes — 2 hours 25 minutes** |
| Recorded accounting status | **POSTED** |

The elapsed-time calculation is **20:25:00 − 18:00:00 = 8,700 seconds ÷ 60 = 145 minutes**. Timestamps are reproduced exactly as stored; the source does not specify a timezone.

### Policy conclusion

**The recorded POSTED status is inconsistent with Oracle’s documented Pending Close treatment for this event.** Oracle states that new transactions created after the Pending Close date, even when they relate to the current or a prior period, will not be staged or processed until the period is closed or reopened.

Oracle permits continued processing for revenue lines, COGS recognition, and manual cost adjustments. This event is an **INPUT component issue**, not one of those exceptions.
